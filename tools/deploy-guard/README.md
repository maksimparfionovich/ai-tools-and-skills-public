# deploy-guard

PreToolUse-хук Claude Code: технически не даёт агенту выкатить **прод или UAT** из shell-команды.
Нужен, если выкатка на прод у вас запускается тегом, веткой, GitHub Release или записью в
gitops-репозиторий, и вы хотите, чтобы прод катил только человек — даже если агент пойдёт в обход
своих инструкций.

Только стандартная библиотека Python 3.8+.

## Что блокирует

| Команда | Почему |
| --- | --- |
| `git push`, в котором есть подстрока `release` | во многих CI тег или ветка с `release` (даже `prerelease`) катит прод |
| `git push` со словом `prod` или `uat` (отдельным словом: `fix-prod-x` — да, `production` — нет) | тег или ветка с этим словом катит прод или UAT |
| `git push --tags` / `--mirror` / `--follow-tags` | пачкой могут уйти релизные теги |
| в gitops-репозитории (`argocd` или `gitops` в команде или в рабочей папке): `git push` в `main`/`master`, `git push` без явной ветки или с `HEAD`, `--all`; `gh pr merge` и мерж через API | выкатывается то, что лежит в `main`. **Ветки пушить можно**: правка — веткой и PR, мержит человек |
| `gh release create/edit/upload`, POST в `/releases` через `gh api` или `curl` | опубликованный релиз уезжает на прод |
| `gh workflow run`, `/dispatches`, `/git/refs` с `prod`/`uat`/`release` | ручной запуск сборки на прод и создание тега через API |

Ложные срабатывания осознанные: пуш ветки `fix/prod-502` тоже заблокируется — такие пуши делает
человек. Это касается и веток gitops-репозитория: имя ветки — без `prod`, `uat` и `release`.

Как разбирается пуш в gitops: первый позиционный аргумент после `push` — remote, остальные — refspec;
ветка назначения — часть после `:` (или весь refspec), `refs/heads/` отбрасывается, `+` (force) не
влияет. Без refspec пушится текущая ветка, а её хук не видит, — поэтому такой пуш запрещён. Рабочая
папка берётся из поля `cwd` JSON хука: `cd` в gitops-репозиторий в прошлой команде его не спрячет.

Хук смотрит на текст команды, поэтому срабатывает и на текст внутри неё: правка файла через `sed` или
`python -c`, где встречаются `argocd` и `gh pr merge`, тоже заблокируется — такие правки делайте
редактором. Команда делится на части по `&&`, `||`, `;`, `|` и переводу строки; каждая проверяется
отдельно.

**Не покрывает:** клики в браузере (кнопка Run workflow в GitHub), MCP-инструменты GitHub, пуши из
скриптов через `subprocess` — хук видит только текст команды, которую агент передаёт в shell.
Скрипт выкатки на стенд из этого репозитория (`skills/deploy-to-stand`) проверяет тег сам.

## Настройка

Без настроек работают значения по умолчанию из таблицы выше. Чтобы поменять — скопируйте
`config.example.json` в `config.local.json` рядом со `guard.py` (или укажите путь в переменной
`DEPLOY_GUARD_CONFIG`):

| Поле | По умолчанию | Что задаёт |
| --- | --- | --- |
| `release_substring` | `"release"` | Подстрока, которая в вашем CI катит прод. Пустая строка — не проверять |
| `prod_words` | `["prod", "uat"]` | Слова, которые в теге или ветке катят прод/UAT |
| `gitops_markers` | `["argocd", "gitops"]` | Слова, по которым команда или рабочая папка считается gitops-репозиторием |
| `gitops_protected_branches` | `["main", "master"]` | Ветки gitops-репозитория, куда пушить и мержить нельзя |
| `block_github_release` | `true` | Блокировать публикацию GitHub Release |

Битый `config.local.json` хук не ломает: остаются значения по умолчанию, в stderr — предупреждение.

## Подключение

В `.claude/settings.json` проекта:

macOS / Linux:

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [{ "type": "command",
                    "command": "python3 \"$CLAUDE_PROJECT_DIR/tools/deploy-guard/guard.py\"",
                    "timeout": 15 }] }
    ]
  }
}
```

Windows: интерпретатор `python` (в Git Bash `python3` часто оказывается заглушкой Microsoft Store),
matcher `"Bash|PowerShell"`, путь к скрипту — с прямыми слешами.

Блок = код выхода 2 и причина в stderr (UTF-8): вызов не выполняется, причина уходит агенту.

## Проверка

```bash
python3 tools/deploy-guard/test_guard.py
```

Кейсы лежат в файле, а не в командной строке: включённый хук заблокировал бы саму тестовую
команду. Тесты не зависят от вашего `config.local.json`. Безопасная проверка, что хук включён:
команда `echo "test: git push --tags"` должна быть заблокирована.
