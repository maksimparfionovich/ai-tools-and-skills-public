# payload-cms-mcp

MCP-сервер для работы с [Payload CMS](https://payloadcms.com) через стандартный REST API
(`/api/<коллекция>`): статьи, авторы, теги, категории, медиа и любые другие коллекции.
Нужен, чтобы агент (Claude Code, Claude Desktop) сам готовил тестовые данные на dev- и
qa-стендах: создавал и правил документы, загружал картинки, искал записи. Прод при этом
защищён от записи на уровне кода.

Версия: 0.3.1 (см. «Изменения»).

## Что умеет

- Вход по почте и паролю. Схему входа сервер определяет сам: JWT (по умолчанию в Payload) или
  сессия на куках с CSRF-токеном. Двухфакторка — по желанию, через TOTP.
- Инструменты для статей, авторов, тегов и категорий с удобными значениями по умолчанию: статья
  создаётся черновиком, slug генерируется сам, текст принимается в Markdown и превращается в Lexical.
  Эти помощники рассчитаны на схему новостного сайта (коллекции `articles`, `authors`, `tags`,
  `categories`, редакционные статусы); если у вас другая схема — пользуйтесь универсальными
  инструментами ниже.
- Универсальные `cms_find` / `cms_get` / `cms_create` / `cms_update` / `cms_delete` для любой
  коллекции: поля передаются как есть, поэтому изменения схемы CMS их не ломают.
- Загрузка файлов (`cms_upload`) в коллекции с `upload: true`.
- `cms_request` — запрос к любому REST-эндпоинту, если готового инструмента нет.
- `cms_schema_doctor` — показывает, чем схема CMS разошлась с сохранённым снимком.

## Защита от записи

Создание, правка, удаление и загрузка файлов проверяются **до входа в CMS**: заблокированный запрос
в сеть не уходит. Правила:

1. Хост из `CMS_READONLY_HOSTS` — только чтение, всегда. Сюда — прод, UAT и всё, что работает на
   прод-базе. Этот список сильнее всех остальных.
2. `localhost`, `127.0.0.1`, `::1` — запись разрешена.
3. Хост из `CMS_ALLOW_WRITE_HOSTS` — запись разрешена. Сюда — ваши dev- и qa-стенды.
4. Любой другой хост — только чтение.

Без настроек сервер пишет только на `localhost`. Синтаксис списков (через запятую, регистр не важен):

| Запись | Что совпадает |
| --- | --- |
| `cms-qa1.example.com` | ровно этот хост (можно вставить URL целиком — берётся имя хоста) |
| `cms-qa*.example.com` | `*` — любые символы, кроме точки: `cms-qa1`, `cms-qa2`, … |
| `*.example.com` | сам домен и все поддомены любой глубины |

`cms_whoami` и `cms_set_target` показывают в поле `writes`, разрешена ли запись на текущем стенде и
почему.

Почта и пароль хранятся в конфиге клиента открытым текстом (`~/.claude.json`,
`claude_desktop_config.json`). Не кладите эти файлы в синхронизируемые папки и заводите для агента
отдельного тестового пользователя стенда, а не личную учётку.

## Установка

```bash
cd tools/payload-cms-mcp
npm ci
npm run build        # собирает dist/
npm test             # защита от записи и вход — на поддельном сервере, без сети
```

Нужен Node.js 18.17 или новее.

## Переменные окружения

| Переменная | Обязательна | Что задаёт |
| --- | --- | --- |
| `CMS_EMAIL`, `CMS_PASSWORD` | да | Тестовый пользователь стенда |
| `CMS_BASE_URL` | нет | Стенд по умолчанию, например `https://cms-qa1.example.com`. Обычно не задают: стенд выбирают в чате (`cms_set_target`) |
| `CMS_ALLOW_WRITE_HOSTS` | нет | Где разрешена запись, кроме `localhost` (синтаксис — выше) |
| `CMS_READONLY_HOSTS` | нет, но очень желательно | Где запись запрещена всегда: прод, UAT |
| `CMS_LOCALES` | нет | Локали CMS через запятую — для `cms_list_locales` |
| `CMS_USERS_COLLECTION` | нет | Коллекция пользователей для входа, `users` |
| `CMS_LOGIN_PATH` | нет | Свой адрес входа. По умолчанию — `/api/auth/login`, а если его нет (404) — стандартный `/api/<CMS_USERS_COLLECTION>/login` |
| `CMS_TOTP_SECRET` | нет | base32-секрет, если у пользователя включена двухфакторка |
| `CMS_DEFAULT_LOCALE` | нет | Локаль по умолчанию, `en` |
| `CMS_DEFAULT_DEPTH` | нет | Глубина подтягивания связей при чтении, `1` |
| `CMS_TIMEOUT_MS` | нет | Таймаут запроса, `30000` |
| `CMS_HTTPS_PROXY` | нет | Прокси для исходящих запросов; иначе берутся `HTTPS_PROXY` / `HTTP_PROXY` |
| `CMS_PAYLOAD_TYPES_PATH` | нет | Путь к `src/payload-types.ts` в клоне репозитория CMS — для `cms_schema_doctor` |
| `CMS_CONFIG_FILE` | нет | Другой путь к файлу настроек вместо `config.local.json` (ниже) |

### Файл настроек `config.local.json`

Несекретные настройки — хосты, локали, адрес входа — удобно держать не в конфиге клиента, а в
`config.local.json` рядом с `package.json` (пример — `config.example.json`, в git файл не идёт):

```json
{
  "CMS_ALLOW_WRITE_HOSTS": "cms-dev*.example.com,cms-qa*.example.com",
  "CMS_READONLY_HOSTS": "cms.example.com,*.prod.example.com",
  "CMS_LOCALES": "en,de,es,fr"
}
```

Ключи — те же имена, что у переменных окружения; значение — строка или массив строк. Файл заполняет
только то, что не задано в env: переменная окружения всегда сильнее. Почту, пароль и
`CMS_TOTP_SECRET` из файла сервер не берёт — им место в конфиге клиента.

Зачем: один и тот же сервер часто описан в нескольких местах — в `~/.claude.json` для Claude Code, в
`claude_desktop_config.json` для Claude Desktop, в плагине. Файл настроек читает каждый запущенный
экземпляр, и не нужно переписывать три конфига. Какой файл подхватился и какие ключи из него взяты —
видно в ответе `cms_whoami` (поле `settingsFile`) и в первой строке лога сервера.

## Подключение к Claude Code

macOS / Linux:

```bash
claude mcp add payload-cms --scope user \
  --env CMS_EMAIL=<почта> \
  --env CMS_PASSWORD=<пароль> \
  --env CMS_ALLOW_WRITE_HOSTS='cms-dev*.example.com,cms-qa*.example.com' \
  --env CMS_READONLY_HOSTS='cms.example.com,*.prod.example.com' \
  -- node "$HOME/<путь к клону>/tools/payload-cms-mcp/dist/index.js"
```

Windows (Git Bash или PowerShell) — путь с прямыми слешами, тогда ничего не нужно экранировать:

```bash
claude mcp add payload-cms --scope user --env CMS_EMAIL=<почта> --env CMS_PASSWORD=<пароль> --env CMS_ALLOW_WRITE_HOSTS=cms-qa*.example.com --env CMS_READONLY_HOSTS=cms.example.com -- node "C:/<путь к клону>/tools/payload-cms-mcp/dist/index.js"
```

Проверить: `claude mcp list`. Стенд выбирается в чате: «работай с qa1» — агент вызовет
`cms_set_target` с адресом стенда (адреса удобно держать в карте окружений — скил `stand-topology`).

## Подключение к Claude Desktop

Настройки → Connectors → добавить локальный (stdio) MCP-сервер: команда `node`, аргумент — полный
путь к `dist/index.js`, переменные — как выше.

Если правите конфиг файлом (`~/Library/Application Support/Claude/claude_desktop_config.json`
на macOS, `%APPDATA%\Claude\claude_desktop_config.json` на Windows), сначала полностью
закройте приложение — иначе оно перезапишет файл своей копией.

## Проверка связи

```bash
cp .env.example .env     # вписать CMS_BASE_URL стенда, почту, пароль и CMS_ALLOW_WRITE_HOSTS
npm run smoke
```

Создаёт черновик статьи, читает его и удаляет. В конце — `SMOKE TEST PASSED ✅`. Стенд должен быть
в `CMS_ALLOW_WRITE_HOSTS` (или это `localhost`), иначе запись заблокируется.

## Инструменты

| Инструмент | Что делает |
| --- | --- |
| `cms_whoami` | Проверка связи: версия сервера, стенд, разрешена ли запись, файл настроек, пользователь, роли |
| `cms_set_target` | Сменить стенд (и при необходимости пользователя) до перезапуска сервера |
| `cms_list_locales` | Локали из `CMS_LOCALES` и локаль по умолчанию |
| `cms_create_article` / `cms_update_article` | Создать статью (черновиком, текст в Markdown) / изменить; публикация — `status=published` |
| `cms_create_author` / `cms_create_tag` / `cms_create_category` | Автор, тег, категория; slug — сам |
| `cms_upload` | Загрузить локальный файл в коллекцию для файлов |
| `cms_find` / `cms_get` | Поиск и чтение документов любой коллекции |
| `cms_create` / `cms_update` / `cms_delete` | Создание, правка, удаление в любой коллекции |
| `cms_request` | Запрос к любому REST-эндпоинту |
| `cms_schema_doctor` | Расхождение схемы CMS со снимком |

Подсказки по данным: в многоязычной CMS передавайте `locale` для нужного перевода. Связи (`author`,
`category`, `tags`) принимают id документов: сначала найдите или создайте автора и категорию.

## Известные ловушки

- **Стенд сбрасывается при перезапуске сервера.** Выбранный в чате стенд живёт только в памяти
  процесса; после перезапуска запросы уходят на `CMS_BASE_URL` (или никуда). Перед записью и
  перед выводами вызывайте `cms_whoami`.
- **Конфиг читается один раз при старте.** Поменяли почту, пароль или списки хостов — перезапустите
  сервер (в Claude Code — новая сессия или `/mcp` → reconnect). Это же нужно после `npm run build`:
  запущенный процесс держит старую сборку. Описания инструментов клиент может кэшировать — версию
  сервера проверяйте по ответу `cms_whoami` (поле `writes` есть с 0.2.0).
- **`401 Invalid credentials` Payload отдаёт на любую ошибку входа:** неверный пароль, заблокированный
  пользователь. Сначала проверьте, что сервер запущен с актуальными данными.
- **Поля могут не записаться молча.** Если у поля в коллекции закрыт `access.create`/`access.update`
  для роли тестового пользователя, Payload отвечает «успешно» и просто отбрасывает поле. Перечитайте
  документ после записи; при сомнениях пишите тело через `cms_request`.
- **POST к `/api/graphql` через `cms_request` считается записью** и на read-only хостах блокируется.
  Для чтения используйте REST (`cms_find`, `cms_get`).

## Два режима входа

Вход — `POST` на `CMS_LOGIN_PATH`, по умолчанию `/api/auth/login` (свой эндпоинт входа, если в CMS
стоит плагин авторизации), а если его нет — стандартный `/api/users/login`. Режим выбирается по
ответу, настраивать ничего не нужно.

- **JWT** (стандартный Payload): в ответе `token`, запросы идут с `Authorization: JWT <token>`.
- **Сессия на куках** (плагин авторизации): в ответе `{authenticated: true}` и куки
  `__Host-cms_session`, `__Host-cms_csrf`. Запросы на изменение дополнительно несут `Origin`,
  `Sec-Fetch-Site: same-origin` и `x-csrf-token`. Срок сессии берётся из `GET /api/auth/session`; на
  `401` и `403` клиент один раз входит заново.
- **Двухфакторка** (плагин авторизации): ответ `{requires2fa, pendingToken}`, код TOTP уходит на
  `POST /api/auth/2fa-verify`.

`cms_set_target` сбрасывает режим, так что стенды с разными схемами входа можно чередовать.

## Если поменялась схема CMS

1. В клоне репозитория CMS: `pnpm generate:types` (или `payload generate:types`) — обновить
   `src/payload-types.ts`.
2. `cms_schema_doctor` — посмотреть расхождения со снимком.
3. Если они задевают значения по умолчанию в помощниках для статей — поправить `src/index.ts`.
   Универсальные `cms_*` и `cms_request` работают без правок.
4. Обновить снимок: `npm run sync-schema -- <путь к репозиторию CMS>/src/payload-types.ts`.
   Снимок (`schema.snapshot.json`) — данные вашей CMS, в git он не идёт; путь в нём пишется от папки
   репозитория, без личных папок.

## Платформы

Разрабатывался и проверялся на Windows 11 (Git Bash, Claude Code, Claude Desktop). Код от системы
не зависит — обычный Node.js без системных вызовов. Проверка на Linux — см. раздел «Проверено» в
README репозитория; на macOS не проверялся.

## Изменения

- **0.3.1** — несекретные настройки можно держать в `config.local.json` рядом с пакетом (env сильнее);
  `cms_whoami` показывает версию сервера и файл настроек.
- **0.3.0** — адреса стендов вынесены в настройки: запись разрешена на `localhost` и хостах из
  `CMS_ALLOW_WRITE_HOSTS` (маски `*`), хосты из `CMS_READONLY_HOSTS` — только чтение без исключений;
  локали — из `CMS_LOCALES`; вход — `CMS_LOGIN_PATH` или `/api/auth/login` с переходом на стандартный
  `/api/users/login`, если первого нет; путь в снимке схемы — от папки репозитория CMS; `npm test`
  проверяет защиту от записи и вход на поддельном сервере, без сети.
- **0.2.0** — запрет записи на прод и UAT; `cms_whoami` и `cms_set_target` показывают, разрешена ли
  запись.
- **0.1.x** — вход через сессию на куках; первая версия.

## Структура

```
tools/payload-cms-mcp/
├── src/
│   ├── index.ts      # MCP-сервер и инструменты
│   ├── client.ts     # клиент CMS: вход, REST, загрузка
│   ├── guard.ts      # защита от записи: CMS_ALLOW_WRITE_HOSTS / CMS_READONLY_HOSTS
│   ├── lexical.ts    # Markdown / текст → Lexical
│   ├── schema.ts     # снимок схемы и cms_schema_doctor
│   ├── config.ts     # настройки из переменных окружения
│   ├── totp.ts       # TOTP для двухфакторки
│   ├── qs.ts         # сериализация запроса where
│   └── util.ts       # slug, MIME-типы
└── scripts/
    ├── guard-test.ts # npm test: правила защиты от записи
    ├── client-test.ts # npm test: вход, запрет записи и файл настроек на поддельном Payload
    ├── sync-schema.ts
    └── smoke-test.ts
```
