# menu-seed

Поддержка сида меню для CMS на Payload: снять меню прода по всем локалям в JSON-сид, проверить
данные, сравнить с сидом в репозитории, записать новый сид и сверить стенд после заливки.

Нужен, если меню на стендах заливается скриптом из сида (например, `src/scripts/create-menu.ts`,
который читает `src/scripts/data/menu-seed.json`), а эталон меню — прод. Рассчитан на коллекцию
меню с полями `title`, `link`, `category`, `position`, `openInNewTab`, `nofollow`, `isActive` и
вложенными пунктами `children` (GraphQL-запрос `Menus`). Под другую схему поправьте `QUERY` и
`to_seed()` в скрипте.

Только стандартная библиотека Python 3.8+ и `git`. Ставить ничего не нужно.

## Настройка

`config.local.json` рядом со скриптом (пример — `config.example.json`), файл из `MENU_SEED_CONFIG`
или `--config`:

| Поле | Что задаёт |
| --- | --- |
| `prod_graphql` | GraphQL прода — откуда снимается меню (`refresh`) |
| `stand_graphql` | Шаблон GraphQL стенда, `{stand}` подставляется (`verify`) |
| `repo` | Рабочая копия репозитория CMS, где лежит сид |
| `seed_path` | Путь к сиду внутри репозитория |
| `locales` | Локали в порядке ключей сида |
| `copy_from` | Локаль без меню на проде → откуда взять структуру, например `{"fr": "en"}` |
| `user_agent` | User-Agent запросов: стандартный `Python-urllib` часть WAF режет 403 |
| `category_from_graphql` | GraphQL отдаёт enum без дефисов, а в коллекции категории с дефисом |

## Формат сида

- **Только активные пункты.** Снимок снимается анонимным GraphQL, а анониму Payload обычно отдаёт лишь
  `isActive: true`.
- **Позиции — как на проде, с дырами.** Дыра в блоке (0, 1, 3) — это слот отключённого на проде пункта.
  Не закрывать.
- **Копия локали.** Если у локали на проде меню нет, туда кладётся структура из `copy_from`; это
  записывается в `_meta`.
- **`_meta.capturedAt`** — дата снимка. Остальные поля `_meta` описывают, что в сиде есть и чего нет.

## Команды

```bash
# 1. Изменился ли прод? Ничего не пишет: снимает прод, сравнивает с сидом из origin/main, проверяет данные.
python3 tools/menu-seed/menu_seed.py refresh

# 2. Записать новый сид. Репозиторий CMS должен стоять на фича-ветке, и её имя надо назвать явно.
python3 tools/menu-seed/menu_seed.py refresh --write --branch chore/menu-seed-YYYY-MM-DD

# 3. Сверить стенд с сидом (по умолчанию сид из origin/main, все локали).
python3 tools/menu-seed/menu_seed.py verify --stand qa2
python3 tools/menu-seed/menu_seed.py verify --stand qa2 --locale en
python3 tools/menu-seed/menu_seed.py verify --stand qa2 --seed path/to/menu-seed.json   # сид из ветки
```

`verify` возвращает 1, если хоть одна локаль разошлась. Общие ключи: `--repo` (по умолчанию — поле
`repo`), `--ref` (по умолчанию `origin/main`). Перед `refresh` и `verify` сделать `git fetch` в
репозитории CMS. На Windows — `python` вместо `python3`.

## Как обновить сид, если прод поменялся

1. `git fetch` в репозитории CMS, затем `refresh` без записи. Смотреть три блока: объёмы, поэлементные
   изменения, данные прода.
2. **Данные прода, которые сид унаследует.** Если `refresh` пишет про дубль `position`, пробелы в
   заголовке, `http://` или не-URL в `link` — это дефекты прода. Обычно сначала правят прод, потом
   переснимают снимок. Дубли `position` в Payload правятся перетаскиванием в списке коллекции в
   админке (локаль переключается глобально, вверху); перетаскивание перенумеровывает весь блок.
3. В репозитории CMS создать фича-ветку от `origin/main`. Если рабочая копия занята другой веткой —
   `git worktree add` в отдельную папку и запуск с `--repo` на неё.
4. `refresh --write --branch <ветка>`. Скрипт пишет файл с LF и обновляет `capturedAt`.
5. Проверить в ветке типы и линтер скрипта заливки. Код скрипта при обновлении сида не меняется.
6. Коммит, push, PR. В описании — что изменилось на проде (блок «поэлементные изменения» из `refresh`).

## Ловушки

| Что | Как правильно |
| --- | --- |
| Анонимное чтение меню не видит `isActive: false` | «пункта нет» и «пункт отключён» снаружи не различить; выводы об отсутствии — только после авторизованного чтения |
| GraphQL отдаёт категории `mobile_left`/`mobile_right` | в коллекции и в сиде — `mobile-left`/`mobile-right`; переводит `category_from_graphql` |
| Python на Windows пишет CRLF | `--write` пишет с `newline="\n"`; при ручной правке проверять |
| WAF отдаёт 403 на User-Agent `Python-urllib` | скрипт шлёт свой User-Agent (`user_agent`) |
| `kubectl exec -i … < файл` может молча положить пустой файл | заливать сид в под через `kubectl cp` и сверять `md5sum` |
| Git Bash превращает `/app/...` в Windows-путь | `MSYS_NO_PATHCONV=1` перед `kubectl` |
| `parent` в коллекции с `ON DELETE SET NULL` | удаление родителя первым поднимает детей в корень — при зачистке удалять детей раньше |

После заливки на стенд — `verify --stand <стенд>` плюс авторизованный счёт пунктов (например, через
`payload-cms-mcp`): общее число должно равняться сумме по сиду, отключённых — 0.
