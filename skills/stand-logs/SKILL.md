# Логи из Loki (lokilogs) — стенды и прод

Прямой доступ к Loki по mTLS через тонкий клиент `lokilogs` (исходники и сборка —
`tools/loki-client/`). За секунды вытаскивает логи пода по стенду, сервису, времени и фильтру — во
время выкатки, прогона тестов и при разборе прод-алертов. Стенды и прод обслуживает один и тот же
Loki и один клиент: отличается только namespace.

Факты проекта — какие namespace у стендов и прода, какие алиасы и группы в пресетах, какой фон в
логах считается нормой, где лежат сертификаты — в `local.md` рядом с этим файлом (пример —
`local.example.md`). Прочитай его перед первым запросом в сессии.

## Доступ

Клиенту нужны переменные `LOKI_URL`, `LOKI_CERT`, `LOKI_KEY` (обычно в `~/.config/loki-client/env`) и,
по желанию, пресеты (`presets.local.json` рядом с бинарём или `LOKI_PRESETS`). Подробно —
`tools/loki-client/README.md`.

- Нет сертификатов или файла env — сказать пользователю, чего не хватает (сертификаты выдаёт тот, кто
  администрирует Loki), и остановиться. Не пытаться обойти отсутствующий доступ.
- Нет сети до Loki с этой машины (облачная песочница, VPN выключен) — так и сказать; не притворяться,
  что запрос сработает.
- Нет бинаря — собрать (`go build`, см. README клиента) или взять `lq.py` (только Python 3, сырой
  LogQL).

## Запуск

```bash
. ~/.config/loki-client/env && lokilogs query --stand qa1 --app backend --since 15m
```

Путь к бинарю — в `local.md` (если он не в `PATH`). На Windows бинарь называется `lokilogs.exe`.

```bash
lokilogs query  --stand qa2 [--app auto] [--since 1h] [--grep RE] [--level error] [--limit 200]
lokilogs query  --stand prod --app backend --since 30m --grep 'error|fatal'          # прод
lokilogs query  --query '{namespace="<ns>", cluster="<кластер>"} |~ "(?i)timeout"' --since 30m
lokilogs labels [--name namespace|app|cluster]                                       # что вообще есть
lokilogs presets                                                                     # какие пресеты загружены
```

- `--stand` — лейбл `namespace` в LogQL или алиас из пресетов; несколько — через запятую.
- `--app` — `auto` (по умолчанию: набор сервисов по namespace из пресетов, незнакомый namespace —
  целиком, с предупреждением в шапке), `all` — весь namespace, группа из пресетов или имена сервисов.
- `--since` — окно назад: `30m`, `2h`, `1d`. Время в выводе — локальное время машины (`--utc` — UTC).
- `--grep` — регулярка по строке без учёта регистра (`|~` в Loki).
- `--level` — по полю уровня JSON-лога; шкалы у сервисов разные, клиент выбирает по имени сервиса
  (`syslog_scale_apps` в пресетах). У сервисов с текстовыми логами без поля уровня `--level` ничего
  не найдёт — пустой ответ не значит «ошибок нет», ищи `--grep 'error|fatal'`.
- `--limit` — до 5000; `--raw` — показать JSON-конверт целиком (там нода, namespace и **образ
  контейнера** — по нему видно, какой код сейчас на стенде); `--json` — сырой ответ Loki.

## Бережность к общему Loki

Одиночные запросы, окно 15–30 минут, `--limit` не больше 5000, сначала узкий `--grep` и конкретный
`--app`, расширять — только если пусто или непонятно. Прод шумит на порядок сильнее стендов: там
почти всегда нужен `--grep`, иначе упрёшься в `--limit` и получишь срез не того окна.

## Как читать вывод

```
2026-10-20 15:21:25  [frontend/<pod>]  [error]  Page render failed  statusCode=500  path=/news/x
```

то есть `время [сервис/под] сообщение`. Выводы делать по содержимому строк, а не по факту их наличия.

- Пустой результат (`lines=0`) — стенд молчал в этом окне: расширь `--since`, сними `--grep`/`--level`,
  проверь `--app` и namespace (`lokilogs labels --name namespace`).
- Фоновый шум (то, что на ваших стендах и проде считается нормой: 404 от ботов, предупреждения
  драйверов, ненастроенная почта на стенде) перечислен в `local.md` — из выводов его исключать.
- Тег образа в `--raw` (`container_image`) подтверждает, какой код на стенде; имя ветки в теге ничего
  не доказывает — сверяй SHA.

## Разбор прод-алерта

Окно вокруг времени алерта (`--since` чуть шире интервала), тот сервис, на который алерт, и `--grep`
по симптому из алерта (эндпоинт, код, текст). Инцидент — это всплеск 5xx, fatal, паник, крэш-луп
пода; рутинный фон из `local.md` в выводы не брать. Если прод живёт в нескольких регионах или
кластерах, проверь, что алиас `prod` покрывает их все (`lokilogs presets`), иначе перечисли
namespace руками.

## Вместе с выкаткой и тестами

- **После выкатки** (`deploy-to-stand`): смоук красный дольше ~12 минут — не гадать, а снять логи:
  `lokilogs query --stand <стенд> --app <сервис> --since 15m --grep 'error|fatal|ECONN|listen'`.
  Отличить «пул к базе лёг» (нужна перевыкатка) от реального дефекта кода по содержимому.
- **Упал тест:** окно вокруг прогона и сервис под тест, `--grep` по эндпоинту или ошибке из отчёта.
- **Висит SSR или фетч фронта:** логи фронта на таймауты и ошибки запросов к бэку, и адреса, по
  которым фронт ходит в бэк.
- **Ассеты с CDN:** если стенд раздаёт файлы сборки с CDN или из бакета, их 404 до подов не доходят —
  в Loki искать бесполезно, смотреть ответы CDN.

## Границы

Клиент только читает (`query`, `labels`) — ничего не меняет. Выкатка кода — `deploy-to-stand`;
разовые операции над базой — `run-db-script`; метрики и дашборды — не сюда.

## Происхождение

Скил и клиент написаны коллегой; у нас доработаны: несколько namespace и алиасы стендов, подбор
сервисов по namespace и группы, разные шкалы уровней по имени сервиса, читаемый вывод вложенных
JSON-сообщений, пресеты вынесены из кода в JSON, тесты. Подробно — `tools/loki-client/README.md`,
раздел «Происхождение».
