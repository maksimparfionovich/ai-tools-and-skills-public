# Факты окружения для task-review (пример)

Скопируйте в `local.md` рядом и заполните своими данными. `local.md` в git не идёт.

## Где код

- Репозитории сервисов — `/work/repos/<группа>/<repo>`. Эталон — `main` или ref контура, на котором
  будет работать исполнитель.
- Чужую рабочую копию не переключать: читать нужную версию через `git show <sha>:<path>` и
  `git grep <pattern> <sha>` после `git fetch`.
- Что развёрнуто на контуре: версии образов — `/work/repos/gitops-versions/<сервис>/<стенд>`;
  где развёрнуто приложение — описания кластеров в gitops-репо. Потребителей ищите во всех
  кластерах и регионах.

## Стандарты

- Общий слой (WER, workspace-rules, wave-authoring, ORS) — репозиторий `example-org/ai-standards`,
  ветка `main`. Локальный клон — `/work/ai-standards` (`git fetch`, читать `origin/main`).

## Субагенты

- Субагент сверки (только для объёма) — модель уровня Sonnet (Claude Code: Agent с `model: sonnet`
  или профиль `exec-sonnet-medium`, если установлен; Codex — Terra/medium). Свежий взгляд — модель
  сессии.

## Где можно проверять самому

- Только чтение: стенды `qa1`, `qa2` (логи, `kubectl get/logs`, API без записи).
- Остальные стенды, прод, хранилище секретов — запрос доступа (корзина B).

## Куда писать результат

- Задача из трекера — файл `TASKREVIEW-<repo>-<N>.md` в рабочей папке.
- Черновик `ISSUES-*.md` — правки в нём же, результат — рядом.

## Публикация правок

- Задачи GitHub: одно «да» владельца в чате на показанный список. Текст — файлом:
  `gh issue edit <N> -R <org>/<repo> --body-file <файл>`. После — `gh issue view --json body` и
  сравнение с файлом.
- Jira — только чтение.
