# Кейсы task-review

Кейс — настоящая задача в том виде, в каком её завели, и список того, что проверка должна найти и
чего поднимать не должна. Папка `cases/` в открытую копию скила не идёт: тексты задач внутренние.

| Кейс | Задача | Тип |
| --- | --- | --- |
| `E1-workers-wait-for-migrations` | две связанные: скрипт в сервисе и подключение в двух gitops-репо | инфраструктура, gitops |
| `E2-hidden-articles-count` | баг доступа с предложенным фиксом | баг, доступ к данным |

## Как прогнать

1. Свежий агент без контекста разработки скила. В задании: путь к `SKILL.md`, путь к
   `cases/<кейс>/input.md`, куда записать результат (вне workspace, например scratchpad).
2. Запреты в задании: не читать `expected.md` и другие кейсы, файлы `TASKREVIEW-*`, `ISSUES-*`,
   `PLAN-task-review-skill.md` в корне workspace и заметки памяти о задачах кейса; не переключать
   рабочие копии; не ходить на стенды и прод; ничего не писать в GitHub и Jira.
3. Сверить результат с `expected.md`: каждая строка «Должна найти» найдена с верным основанием,
   ничего из «Не должна поднимать» не поднято. Итог — строкой в таблицу ниже.

Слепота прогона. Агент в этом workspace сам получает индекс памяти, а там есть строки о задачах
кейсов. Что попало в контекст, агент пишет в строке «Ограничения» результата, а прогон помечается в
заметках. Полностью слепой прогон — в сессии без памяти workspace.
